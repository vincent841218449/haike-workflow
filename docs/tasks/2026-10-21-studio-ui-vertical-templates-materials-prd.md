# 工作台UI、完整竖屏模板与文案找素材：需求及实施合同

日期：2026-10-21。依据用户三张截图及本机4188核查整理。本文为需求合同，实际实施及逐项缺口见[第一轮验收](2026-10-21-studio-integration-acceptance.md)。部分本地功能已实现，尚未全部交付；既有581字/110秒成片不改写。

实施授权：用户随后要求按本方案执行，并确认MediaCrawler已有许可、素材可用。按该确认启用本地已授权采集/素材流程，不重复要求许可；仍保存来源与使用记录。本轮先用既有声画、隔离供应商及有界真实素材检索验证，不新增付费配音/数字人，不部署或发布。原任务、个人密钥及用户既有Taskmaster改动保留。

## 1. 目标与实际差距

用户应能在同一工作区完成：输入文案 → 选择完整9:16模板 → 选择音色/人物 → 确定素材来源 → 查看本期制作安排 → 提交一次 → 查看真实阶段进度 → 播放、局部替换、下载MP4和可编辑工程。

## 2. 整体UI与组件体系

沿用海客品牌橙、浅中性背景和既有导航，不另起一套无关视觉体系。创作页、任务、资源库、设置共享同一组件规范。

### 2.1 创作页结构

- 顶部仅保留页面标题、草稿保存状态、创作任务入口；已选模板为紧凑摘要，说明移至帮助提示。
- 桌面左侧输入、右侧固定9:16预览；输入按「文案」「声音与人物」「画面素材」三组排列。预览显示官方样片/本期预览两个明确标签，未生成时不写“本期成片”。
- 声音选择后直接按完整文案配音；人物选项依模板能力展示，纯图文/动画模板不强制人物。高级分镜编辑收进“调整画面”。
- 素材来源直接可见：自己的素材、抖音匹配、其他已授权素材库。每项有开关、当前状态和优先级；禁止仅保留含义反转的“跳过抖音”复选框。
- 底部固定操作区只展示草稿状态、费用摘要与一个主按钮。预检未通过显示具体缺项和定位入口；服务/模板内部错误不伪装为用户文案错误。
- 390px手机创作页与模板卡片均单列、预览折叠为可展开面板；现有双列模板卡文字窄长，改为一张完整可读卡片。底部操作区不遮挡最后一个字段，不能出现横向滚动。

### 2.2 通用组件合同

| 组件 | 必须统一的行为 |
|---|---|
| 页面标题/分组标题 | 字号层级、说明与操作位置一致，正文不再大量10–11px灰字 |
| 输入/选择/上传 | 标签、帮助、错误、禁用、上传进度、重试、已保存状态一致；拖放和按钮均可操作 |
| 模板卡片 | 官方名称、真实封面、9:16标记、实际接入状态、样片播放、当前选择；加载/失败有明确占位和恢复 |
| 音色/人物卡 | 选择态、试听态、处理中、失败、替换及资源归属一致 |
| 素材卡/片段槽 | 来源、缩略图、采用区间、对应文案、使用权限、替换/锁定和失败原因可见 |
| 对话框/抽屉 | 清晰标题、固定底部动作、独立正文滚动、Esc关闭、焦点留在弹层并返回触发器 |
| 状态/通知 | 就绪、进行中、需操作、失败、完成有文字和图标，不能只依赖红绿颜色 |
| 任务进度 | 显示当前步骤、当前分段/总段、上次查询时间、排队或运行、可恢复动作；无真实进度时使用阶段状态，不编造倒计时 |
| 成片版本 | 所选/实际模板同一主名称、版本可追溯；播放、局部替换、视频/工程下载和费用待核分开 |

建议规范：8px间距体系；正文14–16px、辅助12–13px；常规圆角8–12px；交互热区至少44px。正常小字对比度目标4.5:1，键盘焦点、200%缩放、减少动态效果及读屏状态另做实测，不能凭截图声称合规。文案、人物和声音均不是换模板时可清空的字段。

资源库补充素材来源/权限/已使用片段/失效状态；API设置集中管理登录、服务与授权状态，业务表单不暴露密钥。任务页和制作页使用同一状态机及按钮规则。

## 3. 全部9:16模板替换

### 3.1 范围与迁移

以[官网9:16目录](https://motiongit.com/templates?ratio=9%3A16)当次同步结果为范围，不把网站全部41条当成竖屏数。当前公开核查7款：

|---|---|
| 385712 | 酷炫科技风 · 口播讲解 |
| template-01-integrated-portrait | 现代图文 · 口播讲解 · 竖屏 |
| vibrant-poster-portrait | 活力海报 · 口播讲解 · 竖屏 |
| template-05-native-portrait | 鲜色角色 · 叙事讲解 · 竖屏 |
| template-04-dark-console-portrait | 科技控制台 · 口播讲解 · 竖屏 |
| template-02-expanded-portrait | 纸面透视 · 口播讲解 · 竖屏 |
| template-03-native-portrait | 深色立体 · 多屏展陈 · 竖屏 |

现有基础3款、旧ADu子风格和横屏入口从本次新建模板选择器移除。保留旧文件、注册表、历史任务/成片及冻结版本的读取和恢复能力；不批量迁移历史付费任务，也不删除用户数据。未来目录新增/下架触发管理端同步与差异报告，不能直接开放未经验证的新模板。

官网本次多数包已标2.7.11、活力海报2.7.10；科技风公开缓存存在版本差异。不能把本地2.5.7或任一网页缓存当最终版本，必须实际取包后验签、固定版本和能力。科技风kinetic-user-core/1与其余adu-authored-unit/1分别适配，不假设一套CLI兼容所有包。细节见[官方资料研究](2026-10-21-motiongit-mediacrawler-research.md)。

名称以包清单与官网对应版本为准；slug/作者/比例共同构成稳定身份。04-A等仅作为历史别名可搜索，不再覆盖官方主名称。名称、封面、版本、实际执行模板在选择器、草稿、任务、成片、工程内一致。

### 3.2 “完整融合”的定义

不是复制封面、换色，也不是所有模板套相同title/quote/media三类镜头。每个包必须接通其实际声明的：

1. 完整工程、支持的原生镜头组/组件、原生动画/镜头调度/转场、人物/媒体槽、材质及可用音效。
2. 官方schema、运行器、素材与字体依赖、真实字幕/词级时钟接口、音轨与输出合同。
3. 原生参数编辑、镜头重排、素材绑定、局部替换、预览、最终渲染和可编辑工程导出。
4. 官网样片只证明作者效果，本期预览须由相同冻结计划和真实输入生成；预览/成片不得执行两套布局。

接入矩阵逐包列明“声明能力/适配入口/测试/实际输出证据”。未支持的官方能力须明确标记缺口，不能以组件模式成功冒充原生组已通。最新版本从签名包读取，不硬编码仅接受2.5.7；已验证版本锁定后不被在线更新替换。

“任意模板可开始”指用户提供该模板最小必需输入、服务可用后可正常创建制作任务；不等于任意文案能虚构三步流程、对比数据或多人对话。内容导演选择同包中适配原文的镜头组，按真实音频延展/组合；保留全部原文，不凑样片步骤、不强制截短、不擅自换包。不具备适配能力的包先补合同，在付费前说明具体缺口，不能按钮可点却渲染失败。

### 3.3 单包状态与功能

目录已发现 → 已合法取得原包 → 已验签/依赖就绪 → 合同适配完成 → 原生能力测试通过 → 真实输入渲染/编辑/下载通过 → 可制作。

可选择按钮只对“可制作”开放；待导入/待修复列在管理清单，显示具体阻塞。目标是7款全部达到可制作，清单可见不算完成。允许从已授权包生成本地封面/样片；官网禁止跨站嵌入时不绕过限制、不抓受限资源充当本地样片。

## 4. 文案→素材→模板的统一链路

### 4.1 执行流程

1. 保存文案和模板选择，按场景职责形成内容计划：文案范围、情境/事实画面、核心对象、动作、语气、必用素材、检索短语。规划不改写用户原稿。
2. 先查用户自有素材与已授权素材库，判断覆盖缺口；只有需要网络画面的槽位进入搜索。解释/观点可用模板叙述镜头，不强制每句都外采。
3. 按用户明确选择的来源调用素材Provider。抖音使用已安装适配器；登录失效/验证码需要用户操作时给单一明确入口，不伪装成“搜索无结果”。不跨来源静默替代。
4. 候选保存视频ID、作者、来源页、发布时间、标题、权限依据和检索原因；不是只按热度或标题取前三条。对下载、候选数量、搜索次数及总耗时设限。
5. 下载后完整解码、镜头切分和多宫格实际画面检查，评估“对象/动作/环境/情绪/当前文案”的匹配。标题相关但画面无关应淘汰；来源视频不等于整段都可用。
6. 选择明确in/out区间，检查竖屏裁切后主体、字幕/水印遮挡、清晰度、时效及可用时长。拒绝不合适的带水印素材，不设计擦水印或伪装来源功能。
7. 冻结每个场景的素材ID/SHA、区间、裁切、人声与素材原声策略、使用依据。默认关闭网络素材原声，避免和用户配音重叠；确需引用原声时显式配置区间、增益和混音。
8. 把素材绑定到所选模板原生媒体槽，保留作者动画/转场与人物布局；事实画面和情境示意有区分，不把家庭晚餐素材说成文中真实人物现场。
9. 用真实配音时钟安排时间线并渲染，成片可点到对应文案和素材来源；局部替换只重做该槽位与本地合成，复用原配音/数字人。

若找不到：扩大同义检索一次（次数可配）→用用户已允许的备选来源→同模板内叙述镜头（仅适用于不依赖具体事实展示的片段）→确有必需素材缺口时请求上传或改选该槽位。页面必须显示实际选择及原因。缺素材不自动生图、不重新生成数字人、不改文案或偷换模板。

### 4.2 必须补的接口合同

- ScenePlan：scene_id、source_text_range、visual_role、required_entities/actions、query_variants、must_assets、时钟来源、slot_id。
- SearchResult：provider、query、status、items、source_ids、freshness、error_kind、fetched_at；空结果、过期会话、限流、网络错误彼此独立。
- ClipBinding：asset_id/SHA、source_url/author、rights_basis、source_in/out、timeline_in/out、crop、mute/gain、scene_id、锁定标记、匹配理由。
- TemplateManifest：author/id/version/ratio、包/运行器/schema/capabilities摘要、所需输入、支持的组与槽、依赖、许可证/用户取得依据、adapter_version。
- RenderSnapshot：文案/声音/人物摘要、模板身份、素材绑定、时间线、费用意图、工程及MP4版本关联。变化只使依赖它的阶段失效。

执行时必须让“界面选了抖音”对应实际抖音调用和回执。当前auto绕过Sources的问题应通过统一素材计划/解析阶段解决，不能只把skip_douyin改成false，也不能强行恢复旧固定原生规划器导致581字原稿再次被拒。

## 5. MediaCrawler能力与实际使用边界

MediaCrawler承担平台搜索/详情采集等来源适配；本项目承担语义规划、候选筛选、实际镜头检查、片段区间、权限记录、模板编排与导出。不能把安装爬虫等同于自动剪辑已完成。公开源码和集成边界核查见同日研究文档。

用户在接受本方案时已明确确认MediaCrawler及素材具有许可，本轮按该确认实施已授权本地采集，不再要求重复确认。保留来源页、作者、采用区间和使用依据，不将采集工具的安装状态冒充某条视频的采集结果。

登录凭据仍只存忽略的本地秘密/项目独立浏览器配置；不进日志、工程、Git或导出包。采集不包含点赞、评论、私信、发布，也不绕过验证码和平台限制。

## 6. 阶段、费用和恢复

制作前：模板/能力/登录/素材策略免费本地预检；文案分镜建议与真实音频时间轴有清晰区分，不估计虚假词级时间。已有配音、数字人只按原意图/SHA复用；ASR只对齐字幕，不恢复识别内容和原文数字/否定词一致性门。

执行阶段建议：准备输入 → 匹配素材 → 配音及时间轴 → 数字人分段 → 模板编排 → 本地渲染 → 校验与工程导出。素材检索可在配音前做内容可行性检查，最终切点以真实音轨冻结。界面显示真实当前项；生成阶段耗时无供应商百分比时用排队/运行/最近查询时间，不能长期用43%掩盖排队。

换模板：保留文本/音色/人物/素材，重新计算模板参数和本地画面；已完成付费阶段经身份核对后复用。换某段素材：只失效该段裁切、渲染及依赖输出。任何成功/运行/未知受理的付费请求不因UI重试而重提。新收费动作与已授权范围分开，在一次明确制作确认中展示供应商、计费方式和已有产物复用情况；不反复弹审批。

内部schema、原生规划、字体、渲染错误由程序保存诊断和安全恢复点；用户只看到可执行下一步。费用回执待核不把已完成视频改为未完成；人工发布继续是独立动作。
