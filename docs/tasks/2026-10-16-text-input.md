# 文本请求取消字节上限：本地修改

2026-10-16。用户要求取消文本字节限制；本轮只修改本地源码和隔离测试，不部署、不恢复视频队列、不调用真实供应商。

## 问题与修改

- 原生03-A模板编排请求携带完整动作组信息；复现请求与失败记录指纹一致，共64,201字节。`gateway.clean_input`原来超过60,000字节就返回422“对话文本过长”。
- HTTP中间件还有通用100,000字节检查；仅删除前一项会使更大的合法文本请求仍返回413。
- 删除对话文本的字节拒绝条件；`/v2/quotes`（包括末尾斜线入口）免于通用请求体字节检查。文本原样进入冻结报价及供应商适配器，不裁剪、不拆换模板。其他入口的请求体检查及媒体/归属/参数校验保留。
- 字节长度继续用于现有报价的保守Token用量估算，实际结算仍来自供应商回执；没有更改价格、历史意图、账单或模型输出参数。

## 验证

- 修改前新增5个回归用例全部失败：3个输入校验用例命中422，2个HTTP完整链路用例命中413；修改后全部通过。
- 原64,201字节失败请求经本地真实校验函数原样通过，未发送上游、未恢复队列。
- 60,001、100,001、1,000,001个中文字符直接校验通过；超过100KB的纯文本及结构化文本通过真实HTTP报价、幂等提交、冻结输入、假供应商执行和结果回读。完整消息一致、重复提交仅执行一次、试用实扣零、隔离账本平衡。
- API模块完整回归114项通过；现有DashScope弃用警告保留。测试仅使用临时数据库与假供应商。
- 本次改动文件Ruff通过；全模块Ruff仍有既有`tests/test_bailian_system_voices.py`的3项问题（导入排序、未使用导入/变量），本轮未改该文件。
