## 已复现的原因

1. 之前取消字节检查只修改了本地 API 源码。实际 4188 仍连接旧云端网关；03-A 编排的 64,201 字节请求在报价时被 HTTP 422“对话文本过长”拒绝。原 `except Exception` 吞掉了阶段和异常，只留下“请检查API连接与本地渲染依赖”。
2. 当前原文是两笔商业投入的比较，03-A 固定编舞要求九项、四个版本等结构。原生导演正确拒绝伪造这些事实，但原流程没有同包组件表达路线。
3. 同一任务查询供应商时会重新取得队列执行权，清空进度再读取缓存，导致 43% 闪回 0%；制作中的模板名还错误使用了基础模板名。
4. 下载连接中断或不完整的本地文件，会直接终止任务；半成品存在性也不足以证明本地渲染已完成。

## 生产合同

- 本机显式启用既有 `chat_route=direct` 配置，仍用 `gpt-6-luna`、本机赞助次数及单任务次数控制；未修改客户默认网关、云端密钥或费率。凭据只在忽略的私有配置中。
- 每笔 AI 路由与输入绑定。旧 gateway 请求仅在 prepared、无报价、无网关任务和无 SDK 意图记录时迁移；已受理/未知请求继续原路查询。旧 direct 未知记录也不因默认配置改变而重提。拒绝的报价保存预检类型/HTTP 状态，不执行 confirm。
- 意外异常记录阶段、异常类型、文件/行/函数与诊断编号；不保存异常原文或局部变量，不把密钥暴露在任务页。已知错误保留具体错误码。
- 原父队列保留已完成进度；取消会在下一制作阶段及新数字人提交前生效。已知供应商等待可暂停后续制作和恢复同一任务，不删除原供应商编号。供应商查询、下载断线继续原请求，损坏下载留存后重取；连续三次下载/解码不通过才停止并说明具体步骤。
- 本地成片缓存绑定计划、输入视频、配音及适配器摘要；临时渲染成功核验后才原子转为可复用缓存。完整解码、H.264/AAC、1080×1920、60fps、全部帧数及两条媒体时长验证通过后登记。
